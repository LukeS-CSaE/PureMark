# PureMark 项目认知与现状总览（权威版）

> **本文档是项目当前的唯一权威认知总览**，由工作记忆与 `docs/` 系列设计/PRD 文档对照**真实代码**核订而成（核订日期 2026-08-10）。
> 早期文档（`对齐规格_SoloMD.md`、`system_design.md`、`prd-iter2*`、`design-iter2*`）是**历史基线**，记录"当时怎么设计的"；本文档记录"现在实际是什么样"。凡与本文档冲突处，以本文档为准。
> 改动性质：设计文档里大量"将要做 / 计划做"的条目，代码层面**多数已落地**；少数**未做 / 被注释掉 / 有遗留债**，已在 §4、§7 明确标注。

## 0. 一句话定位

**PureMark** = 基于 **Tauri 2（Rust 壳 + WebView）+ React 18 + CodeMirror 6** 的极简、本地优先（local-first）Markdown 编辑器桌面应用，目标 **Windows `.exe`**。无账号、无云同步、无 telemetry、无导出。用户写作即写纯 `.md` 文件。

## 2. 技术栈（实际依赖）

**前端**：React 18.3 + TypeScript 5.5 + Vite 5.4 + Tailwind CSS v4（`@theme inline` 映射 token）。
**编辑器内核**：CodeMirror 6（`@codemirror/state|view|commands|language`、`@codemirror/lang-markdown`、`@lezer/markdown`）。
**Markdown 渲染**：`marked`（预览区）+ CodeMirror markdown 语法树（live 装饰）。
**代码高亮**：`highlight.js`（预览区 `.hljs-*` 由 `highlight.ts` 按需注册语言 + 自写基于 CSS 变量的配色）。
**状态**：`zustand` v4（4 个 store）。
**图标**：`lucide-react` 0.439。
**桌面壳**：Tauri 2 + 插件 `dialog` / `fs` / `store` / `single-instance`。
**测试**：`vitest`（**`environment: "node"`，无 jsdom**），纯 TS 模块可测；组件交互/CSS 视觉/CM6 行为测不到。

> ⚠️ `@codemirror/state`/`@codemirror/view` 必须单例（`vite.config.ts` 已加 `resolve.dedupe`）；不要装伞包 `codemirror`。

## 3. 架构总览

### 3.1 分层（前端）

```
src/
├── main.tsx                 React 挂载 + 全局 contextmenu 守卫 + 样式 import 顺序(live.css→preview.css)
├── App.tsx                  启动序列：loadConfig→UI→tocRouter.hydrate→panes.hydrate→applyStartupGeometry→take_launch_file→installContextMenuGuard；文件关联监听 open-file
├── types/index.ts           ViewMode / WorkspaceLayout / PaneId / Pane / EditorTab / AppConfig / AccentId / TocItem / WindowGeometry ...
├── store/                   useTabsStore(单 buffer 文档) / useUIStore(视图/侧栏/sidebarMode) / useConfigStore(config v3 + migrate) / usePanesStore(窗格布局/焦点/分屏)
├── lib/                     ★ 纯逻辑层（可 node 单测）：
│                           theme(accent 派生) / windowGeometry / toc / tocRouter / tocRegistry / search / scrollSync /
│                           textDiff / headingAnchors / caret / format / markdown / fileTree / contextMenuGuard / closeGuard /
│                           editorRegistry / paneRouter / editorBridge(历史遗留, 逐步弃用) / tauri(窗口/store/对话框桥接)
├── lib/cm/                  cmTheme / setup / markdownDecor / livePreview / liveRender（CodeMirror 装饰与 live 引擎）
├── hooks/                   useTheme / useToc / useDocSync(CM6 view↔tab 双向同步+EditorHandle注册) / useEditorStats / useAutoSave / useHotkeys
├── components/              AppShell / Header(+WindowControls) / Sidebar(+FileTree+OpenFolderButton+TocPanel 左模式) /
│                           Toc/(TocList,TocPanel) / Workspace/(Toolbar,TabBar,EditorCard,CodeEditor,PreviewPane,ViewSwitcher) /
│                           dialogs/(SearchPanel,SettingsPanel,UnsavedDialog) / ui/(Icon,Button)
└── styles/                  theme.css(:@theme inline token+acrylic) / layout.css / preview.css / live.css / search.css
```

### 3.2 概念分层（iter2 核心模型）

| 层 | 概念 | 取值 | 归属 | 单例/共享 |
|---|---|---|---|---|
| 文档层 | `EditorTab` | 单个共享 buffer（同文件分屏 = 两窗格同一个 `tabId`） | `useTabsStore` | 内容全局唯一 |
| 窗格层 | `Pane.viewMode` | `edit` \| `live` \| `preview` | `usePanesStore.panes[].viewMode` | **每窗格独立** |
| 工作区层 | `WorkspaceLayout` | `single` \| `split` | `usePanesStore.layout` | 全局 |

- **焦点窗格** `focusedPaneId`（A/B）：分屏下 TabBar/侧栏的"打开"动作作用于焦点窗格；状态栏统计、TOC 目录内容来源 = 焦点窗格文档。
- **注册表两套正交**：`editorRegistry`（EditorHandle，仅 edit/live 注册，preview 不注册）/ `tocRegistry`（TocTarget，edit/live 走行定位、preview 走 index 定位）。
- **路由收敛**：打开/聚焦/分屏/关闭只走 `lib/paneRouter.ts`；TOC 开关联动只走 `lib/tocRouter.ts`（组件禁止绕过直接写 store）。

### 3.3 Rust 壳（`src-tauri`）

`main.rs` → `puremark_lib::run()`（lib.rs）。关键：
- **自定义命令**：`build_tree(path)`（递归读目录，仅保留 `.md/.markdown` 与含 md 的目录）、`take_launch_file()`（取出启动期到达的文件路径）。
- **`single-instance` 必须第一个注册**：双击已运行时再双击 `.md` → 新进程退出并 `emit("open-file", path)` 给主窗口 + `set_focus()`。
- **文件关联**：`tauri.conf.json` `bundle.fileAssociations` 注册 `md/markdown`；Windows/Linux 双击 = `PureMark.exe "路径"`（路径在 `std::env::args()`，**不走 macOS 的 `RunEvent::Opened`**）。
- **窗口**：`decorations:false`、`transparent:true`、`windowEffects:["acrylic"]`、`minWidth:960`、`minHeight:480`、`preventOverflow:true`、`center:true`。
- **权限**（`capabilities/default.json`）：window（minimize/toggle-maximize/maximize/unmaximize/close/destroy/start-dragging/set-size/is-maximized）/ dialog / fs(`**`) / store(`**`) + `core:default`。

## 5. 关键工程决策与铁律（来自工作记忆 + 日志，精炼）

1. **类型检查命令铁律**：`npx tsc -p tsconfig.app.json --noEmit`。根 `tsconfig.json` 是 `files:[] + references`，plain `npx tsc --noEmit` 是 **no-op 假通过（永远 exit 0）**，禁止用。
2. **`vite build` 清 dist 的沙箱坑**：本环境 genie-trash 删中文路径 dist 失败（exit 1）。规避：PowerShell `Remove-Item -LiteralPath "<绝对路径>\dist" -Recurse -Force` 强删后再 build。
3. **`node:` 导入需 `tsconfig.app.json` `types:["node","vite/client"]`**，否则 vitest 外的 `node:fs/path/url` 报 TS2307（esbuild 运行时无碍）。
4. **绿测试 ≠ 运行时可用**：vitest 无 jsdom，**跳转/滚动/CSS 视觉/CM6 行为在测试里完全测不到**。此类需求必须在 `pnpm dev` / `pnpm tauri dev` 真机实测，或把核心逻辑抽纯函数单测。
5. **系统级亚克力**走 `transparent + windowEffects:["acrylic"]`；CSS `backdrop-filter` 在 WebView2 下模糊不到桌面（只透出未模糊桌面）。用户已明确"要的就是系统级亚克力"。
6. **Tauri 标题栏拖拽**：`data-tauri-drag-region` 只对**命中元素本身**判断、不遍历祖先。每个可能被命中的非交互容器（header 本体、flex 包裹、文字 span）都要单独挂；button/WindowControls 上不能挂。`<img>` 还必须 `draggable={false}` 否则原生图片拖拽截走指针。
7. **文件关联（Windows）**：双击 = `exe "路径"` 走 `std::env::args()`，**非** `RunEvent::Opened`（仅 Apple/Android）。`single-instance` 必须第一个注册，把二次启动路径 `emit("open-file")`；前端 `listen("open-file")` + `invoke("take_launch_file")` 拉启动前路径。
8. **scrollSync 三场景**（`lib/scrollSync.ts`）：场景1 = 同 split + 同 tabId + 一 editor 一 preview → 同步；其余（独立/tab 不同/都是 editor）不互相同步。纯函数可 node 单测，DOM 层 RAF 防回灌。
9. **配置迁移绝不阻断启动**：`migrateConfig` 包 try/catch；老配置缺 `accent` → `'sky'`（保持原青）、缺 `toc*` → 默认；非法值回落默认。`configVersion` 现 = 3。
10. **vitest 整跑偶发红**：`node_modules/.ignored` 含重复 React 副本，整跑时模块加载顺序竞态 → 偶发 "Invalid hook call"。**以单文件跑为准**（如 `vitest run src/__tests__/editorCardRender.test.ts`）。

## 7. 已知问题 / 遗留债（明确清单）

1. **分屏分隔条不可拖拽**：`splitRatio` 持久化但无 UI 手柄（iter2 R-13 拖拽分隔条未实现，属遗留债）。

3. **live 点击后装饰消失**（8-10 未根治）：已加防御性 try/catch + 空装饰保留上一组，但根因未在 GUI 复现，需用户在 `pnpm dev` 复现并贴回 `[PureMark][DIAG]` 日志。
4. **失焦灰底**：Windows DWM 失焦时停用 acrylic → 面板变灰底（OS 行为，文字仍可读）。精致化可后续 `onFocusChanged` 切 `--acrylic-strong`。
5. **环境类**：整跑 vitest 偶发红（见 §5.10）；`vite build` 清 dist 需 PowerShell 强删（见 §5.2）。
